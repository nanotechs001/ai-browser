# Report: one window with a tab menu, and no popups (tab-menu)

Date: 2026-10-04. Branch `tab-menu`, cut from `main` at 607396d (wave B merged), merged into `main` as 7123816.

## What the user asked

- **Their words:** "also for the UI i do not want a popup new window switching control center, AI home etc. Just
  implement like a tab menu that I can switch in the tab i toggle , add that in pipeline change". They then picked
  "Yes, build it next (Recommended)" for this design:
  - **the tab bar:** a row under the title bar with AI Home · Mission Control · Settings; a click switches the view in
    the same window, and the active tab is marked;
  - **the title** follows the tab ("Mission Control · AI Browser") and keeps AI Home's "(n)";
  - **each view stays alive:** it loads the first time you pick it, then is only hidden, so nothing resets;
  - **extra tabs:** the setup steps and "Show me" open at the end of the bar with a ×; a second Show me for the same
    agent goes to its tab;
  - **no more popups:** links between AI Browser's pages switch tabs; websites still open in your browser;
  - **unchanged:** the plain window, closing it stops the app, and Brave's `ai` keyword.

## What changes for you

- **One window, three tabs:** AI Home · Mission Control · Settings, in a row under the title bar. The tab you're on is
  marked. The window still has no browser tabs, no address bar and no debugging port.
- **The title follows the tab** and keeps AI Home's count of agents at work: "(2) Mission Control · AI Browser".
- **Pages stay as you left them.** A tab loads the first time you pick it. After that, your half-typed message, the
  scroll and Mission Control's room are still there when you come back. A hidden page draws nothing.
- **Closable tabs** at the end of the row, each with a ×:
  - the setup steps (the Brain's **Set it up**, and **Show me how** for Brave's switch, at its own section);
  - an agent's live view (**Show me** on a bot check in QA's sandbox), one tab per agent.
- **No popups.** Buttons and links between our pages switch tabs. A website still opens in your Brave.
- **⌘W (Ctrl+W on Windows and Linux)** closes only the tab you're on, and only if it has a ×. On AI Home, Mission
  Control and Settings it does nothing. Closing the window still stops AI Browser; switching or closing tabs never does.

## How "Show me" became a tab, and why it is safe

- **It could be framed safely,** so it is a tab, not a window:
  - the live view is our own `live.py`, on 127.0.0.1, on ports 8770-8790 only;
  - it sends no header that blocks framing, and both servers keep no request log;
  - the app server never sees its address, and the tab menu sends no referrer;
  - its address is set by script inside the window, so it never becomes a history entry (the old popup's did).
- **Its frame is boxed in:**
  - `sandbox="allow-scripts"`: it can't navigate the window, open a window, send a form or reach our pages;
  - Chrome runs it in a process of its own; its socket to the live view still connects;
  - the tab menu may frame only our pages and those 21 live-view addresses (its CSP);
  - the tab menu never takes a message from it: only our own pages, from our own origin, may ask for a tab.
- **One per agent:** a second Show me shows the same tab. A new live address for that agent re-aims it.

## Rulings I made

Every decision taken on your behalf, in order, with what it costs if wrong:

1. **No test takes 8792:** an autouse guard refuses that port to tests' app servers — cost if wrong: none for the
   product; a test that needed exactly 8792 would fail (none does).
2. **The window's page is `/app`:** the code, a reload and `/` land there; `/home`, `/mission` and `/settings` still
   work by themselves — cost if wrong: one redirect target.
3. **Headers by path:** `/app` may frame our pages and the 21 live-view addresses; our four tab pages may be framed only
   by our own origin; every other answer stays strict — cost if wrong: a live view outside 8770-8790 is blocked.
4. **Hiding:** `visibility:hidden` plus `content-visibility:hidden`, never `display:none` — cost if wrong: Chromium-only
   CSS, and every browser that draws the window is Chromium.
5. **The title** is "(n) <tab label> · AI Browser", with n read from AI Home's own title — cost if wrong: a page that
   renames itself needs its label changed in `app.js` too.
6. **AI Home loads at start,** other tabs when first picked — cost if wrong: none.
7. **Picking a tab moves the keyboard into its page,** so Mission Control's Space to talk works at once — cost if
   wrong: a keyboard user's focus leaves the tab bar on each switch.
8. **Only Mission Control's frame says `allow="microphone"`** — cost if wrong: none.
9. **One call, `openTab(path)`,** replaces both popup calls; no second name — cost if wrong: one more exported name.
10. **Asking for a tab:** a page posts to our own origin; the menu takes it only from its own pages' frames, only for
    our pages or a valid live view, and labels stay text — cost if wrong: none found.
11. **"Show me" is a tab,** for the reasons above — cost if wrong: a future live view that needs its own origin would
    need `allow-same-origin`, safe only while it stays on another port than the app.
12. **One live-view tab per agent** — cost if wrong: none; an agent has one check at a time.
13. **`check.js` stays import-free** (wave D shares it with the watcher): the caller passes `openLive` — cost if wrong:
    the watcher's copy must pass its own.
14. **A page opened by itself** moves to the asked page and ignores live views — cost if wrong: Show me is inert there.
15. **Closing a closable tab** removes its frame and shows the tab before it; fixed tabs have no × — cost if wrong:
    none.
16. **The static guard** forbids any window or popup in `ui/` — cost if wrong: a future window must change the guard.
17. **The old window tests are replaced,** not kept — cost if wrong: none.
18. **The real window's ⌘W, swipe and title bar are hand checks** — a headless run can't show window shortcuts — cost
    if wrong: a shortcut that still closes the window, seen only by hand.
19. **The key** is Command-W on a Mac, Ctrl+W elsewhere, with no other modifier — cost if wrong: a keyboard layout whose
    Command key gives no "w" isn't caught.
20. **The menu and our pages keep the key;** only the page shown may pass it on; a page by itself leaves it to the
    browser — cost if wrong: none found.
21. **In a live view's tab** the menu can't catch the key; the live page now keeps it when framed — cost if wrong:
    `live.py`'s page knows it may be framed.
22. **No `beforeunload` guard** — cost if wrong: none.

## Deferred minors

- `live.py` sends no `frame-ancestors`; its token is its only lock, as before.
- The tab bar has no keyboard shortcuts, and no middle-click close.
- A live view outside ports 8770-8790 would show a blocked frame; `live.py` never binds outside them.
- The pages keep their own AI Home, Mission Control and Settings buttons beside the tab bar. Removing them is your call.
- A reload of the window comes back on AI Home, with only the three fixed tabs.
- A live view's tab stays open after its check is answered, until you close it.
- Closing a background tab leaves the keys going nowhere; refocus the active page then.
- A hidden page could take the keyboard by script; not reachable today; make hidden pages `inert` later.
- A new tab isn't scrolled into view, and the bar hides its scrollbar.
- Re-aiming a loaded frame adds a back/forward step; use `location.replace` later.
- The test fixture `stack` leaks its throwaway Chrome when its setup fails; the main session handles the leaked ones.
- The static guard misses `self.open(variable)`.
- While a tab's page is still loading, nothing catches ⌘W yet; a small script in each page's head would close that gap.
- Ctrl+F4, Windows' other close-tab key, isn't caught.
